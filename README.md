# Generating Music with Machine Learning

UE24CS352A Machine Learning mini-project, Team C-14, Problem 22.
Inspired by the Stanford CS229 (2018) report *Generating music with Machine Learning*.

A MIDI piano performance is turned into a sequence of tokens, a model learns to predict the next token,
and new music is generated by sampling one token at a time and converting the result back to a `.mid` file.
We compare a counting baseline (Markov chain) against an LSTM.

## Approach

| Model | Description |
|---|---|
| **Unigram** | Sanity floor: always the overall token frequencies, no context |
| **Markov baseline** | Order-2 n-gram over tokens, back-off to shorter contexts, smoothed unigram mix |
| **LSTM** | 2 layers, 256 hidden units, 128-d embeddings, dropout 0.2 (~1.06M parameters), Adam, 8000 steps on random 256-token windows |

**Tokens (356):** 128 `NOTE_ON`, 128 `NOTE_OFF`, 100 `TIME_SHIFT` (10 ms to 1 s). Handles chords and real timing.

**Data:** [MAESTRO v3](https://magenta.tensorflow.org/datasets/maestro) piano MIDI. A random 200-piece subset is split
**by piece** 160 / 20 / 20 (fixed seed): 3,240,519 train, 386,786 validation, 363,359 test tokens.
(piano-midi.de, the CS229 dataset, blocks automated downloads.)

## Results

<!-- RESULTS:START -->
| Model | Test loss | Perplexity | Accuracy |
|---|---:|---:|---:|
| Unigram (no context) | 4.4810 | 88.32 | 11.89% |
| Markov (order 2) | 3.8966 | 49.23 | 18.58% |
| LSTM (2 layers, 256 hidden, 8000 steps) | 2.3982 | 11.00 | 32.17% |

Held-out test pieces, 1,419 non-overlapping windows of 256 tokens; all models are scored on the same 361,845 target tokens (`python -m src.evaluate`).
<!-- RESULTS:END -->

The LSTM wins on next-token metrics; loss and accuracy do not fully measure musicality, so a blind listening
survey is also provided (`docs/survey_form.md`).

## Setup

Python 3.10+.

```bash
git clone https://github.com/krrishsingla11/Music-Generation-ML-Mini-Project.git
cd Music-Generation-ML-Mini-Project
python -m venv .venv
# Windows:      .venv\Scripts\activate
# macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt
```

**torch is only needed for training.** The trained LSTM is also stored as plain arrays in `models/lstm.npz`,
and evaluation, generation, the demo and the survey clips all run from that file with numpy only
(useful on machines where Windows blocks torch's DLLs). `data/` is git-ignored, so rebuild it first.

## Run

```bash
# 1. data (MAESTRO, ~60 MB) and tokenization
python scripts/download_maestro.py
python -m src.preprocess --raw data/raw/maestro --max-files 200

# 2. models
python -m src.markov --order 2                 # Markov baseline -> models/markov.pkl
python -m src.train_lstm --steps 8000          # LSTM (needs torch) -> models/lstm.pt
python scripts/export_lstm_npz.py models/lstm.pt models/lstm.npz   # torch-free weights (run where torch works)

# 3. fair evaluation of all models on the same test targets (no torch needed)
python -m src.evaluate                         # add --order3 for the order-3 ablation

# 4. generate / demo
python -m src.generate --model lstm   --tokens 1500 --temp 1.0 --topk 20
python -m src.generate --model markov --tokens 1500 --temp 1.0
streamlit run app.py
```

Quick look without training: `models/lstm.npz` and `models/markov.pkl` are committed, so `streamlit run app.py` works right after
`pip install -r requirements.txt` (without `data/processed/` it falls back to a one-note seed). `src.evaluate` needs the data from step 1.

## Listening survey and report

```bash
python -m scripts.make_survey_clips            # 6 equal-length blind clips + answer key
python -m scripts.analyze_survey responses.csv # after collecting >= 20 responses
python scripts/create_writeup_pdf.py           # docs/music_generation_writeup.pdf
```

## Repository structure

```
app.py                      Streamlit demo
src/
  tokens.py                 vocabulary, MIDI <-> tokens
  preprocess.py             tokenize + piece-level split
  markov.py                 n-gram baseline
  model.py, train_lstm.py   LSTM definition and training (torch)
  numpy_lstm.py             torch-free LSTM inference
  evaluate.py               unified evaluation of all models
  generate.py, audio.py     sampling and built-in synth
scripts/                    data download, torch-free export, survey and PDF tools
docs/                       results, survey form + answer key, final write-up PDF
outputs/                    training logs, results.json, survey clips
models/                     lstm.npz and markov.pkl (committed); lstm.pt is git-ignored
```

`outputs/lstm_log_3000.json` and `outputs/lstm_log_8000.json` are the training logs of the two LSTM runs
(3000 and 8000 steps).

## Limitations

No velocity, key or meter modelling and a single-instrument piano roll; generated audio uses a simple built-in synth
(open the `.mid` in MuseScore or VLC for a real piano sound).
